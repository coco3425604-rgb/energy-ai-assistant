# AI 能源运维助手 MVP 开发计划

## 1. 项目初始化

目标：建立最小且清晰的工程和文档基础。

- 创建 `docs/`、`frontend/`、`backend/`、`tests/` 和 `deploy/` 目录。
- 完成产品需求、系统架构和开发计划文档。
- 后续按实际实现需要初始化前端与后端工程，不提前添加无关依赖。

完成标准：目录结构清晰，三份项目文档齐全，MVP 范围和技术边界明确。

## 2. 文档处理

目标：使约定格式的运维文档能够进入知识库处理链路。

- 实现文档上传与基础校验。
- 实现文本提取、清洗和分段。
- 保存文档元数据、知识片段、来源位置和处理状态。
- 提供处理成功、失败及错误原因反馈。

完成标准：有效文档可被稳定解析为带来源信息的知识片段，无效文档有明确错误状态。

## 3. 知识检索

目标：根据运维问题召回相关企业知识。

- 建立知识片段的检索数据。
- 实现问题检索与相关片段召回。
- 保留召回片段与原始文档的关联。
- 使用代表性运维问题验证检索相关性。

完成标准：测试问题能够返回相关知识片段及可核对的来源信息。

## 4. AI 问答

目标：基于检索内容生成有依据的运维回答。

- 封装服务端大模型调用。
- 组装用户问题、检索上下文和回答约束。
- 返回回答及引用来源。
- 对无充分依据、模型调用失败等情况提供明确反馈。
- 保存问答记录与引用关联。

完成标准：用户可获得基于知识库的带来源回答，并能识别资料不足或服务失败的情况。

## 5. 基础产品化

目标：形成可供 MVP 用户完成核心任务的基础界面和体验。

- 实现文档上传及处理状态页面。
- 实现问答输入、答案和来源展示。
- 实现问答历史列表与查看能力。
- 补充必要的加载、空状态和错误提示。

完成标准：用户可通过前端独立完成文档上传、提问、查看引用和回顾历史的完整流程。

## 6. 测试与部署

目标：验证核心流程，并提供一致的开发和验收环境。

- 为文档处理、知识检索和问答接口补充必要测试。
- 验证上传、解析、检索、问答和历史记录的端到端流程。
- 补充前端、后端和 PostgreSQL 的 Docker 配置。
- 整理环境变量示例、启动步骤和验收说明。
- 验证敏感配置不进入代码仓库。

完成标准：核心流程测试通过，可按文档在 Docker 化环境中启动并完成 MVP 验收。
