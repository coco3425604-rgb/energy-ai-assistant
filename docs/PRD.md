# AI 能源运维助手 MVP 产品需求文档

## 产品目标

建设一个面向企业能源运维场景的 AI 助手 MVP，将分散的设备资料、故障处理文档和历史运维经验沉淀为可检索的知识库，帮助运维人员通过自然语言快速获得有依据的答案，减少资料查找时间并提升经验复用效率。

## 核心用户

- 一线能源运维人员：查询设备资料、故障现象、排查步骤和处理经验。
- 运维技术负责人：沉淀团队知识，辅助一线人员规范、高效地处理常见问题。
- 知识库维护人员：上传和更新企业运维资料，保证知识来源可用。

## 核心用户故事

- 作为知识库维护人员，我希望上传企业运维文档，以便系统能够解析并建立可查询的知识库。
- 作为一线运维人员，我希望用自然语言描述设备或故障问题，以便快速获得基于企业资料的回答。
- 作为一线运维人员，我希望查看答案引用的资料来源，以便核对内容并继续阅读原文。
- 作为一线运维人员，我希望查看历史问答，以便回顾之前的查询和处理思路。
- 作为运维技术负责人，我希望团队能够复用已有运维经验，以便减少重复排查和知识流失。

## MVP 功能

1. 运维文档上传：支持用户提交 MVP 约定格式的企业运维资料。
2. 文档解析：提取文档文本并切分为可检索的知识片段。
3. 知识库构建：保存文档、知识片段及检索所需数据。
4. 知识检索：根据用户问题召回相关的运维知识片段。
5. AI 问答：结合召回内容生成回答，并展示对应资料来源。
6. 问答历史：保存并展示用户的历史问题、回答和引用信息。
7. 基础状态反馈：展示上传、解析和问答过程中的成功或失败状态。

## V1 暂不开发范围

- 自动控制能源设备或下发运维指令。
- 实时设备监控、告警接入和预测性维护。
- 复杂的多组织、多租户和精细化权限体系。
- 面向全部文档类型的高精度解析与 OCR 能力。
- 语音、图片或视频等多模态问答。
- 移动端原生应用和离线使用。
- 自动生成工单、审批流或与外部业务系统深度集成。
- 模型微调、自建大模型训练和复杂智能体编排。

## MVP 验收标准

- 用户能够上传约定格式的运维文档，并看到明确的处理结果。
- 系统能够解析有效文档、生成知识片段，并使其可被后续检索。
- 用户能够通过自然语言提交能源运维问题。
- 系统能够检索与问题相关的知识片段，并基于检索结果生成回答。
- 回答能够展示可核对的文档来源；无可靠资料时应明确说明未找到充分依据，而不是给出无依据的确定结论。
- 用户能够查看已产生的问答历史及其引用信息。
- 文档处理或问答失败时，界面能够提供清晰的错误反馈。
- 核心流程可在 Docker 化的开发或验收环境中运行：上传文档、完成解析、发起提问、查看带来源的回答和历史记录。
