# AI 能源运维助手 MVP 架构设计

## 架构目标

本架构仅服务于 MVP：完成运维文档入库、知识检索、基于检索结果的 AI 问答以及问答历史记录。设计优先保证边界清晰、易于开发和部署，不引入当前阶段不需要的复杂基础设施。

## 系统组成

### Vue 前端

Vue 单页应用负责用户交互，提供文档上传、处理状态展示、知识问答、来源展示和问答历史页面。前端通过 HTTP API 与后端通信，不直接访问数据库或大模型服务。

### Python + FastAPI 后端

FastAPI 提供统一的业务 API，负责：

- 接收文档上传请求并触发解析流程。
- 管理文档、知识片段及其处理状态。
- 接收用户问题，组织知识检索和大模型调用。
- 返回答案、引用来源和错误状态。
- 保存与查询问答历史。

### PostgreSQL

PostgreSQL 作为 MVP 的持久化存储，用于保存文档元数据、解析后的知识片段、检索所需数据、问答记录和来源关联。具体表结构与检索扩展方案在后续实现阶段确定，本次初始化不引入数据库依赖或迁移脚本。

### 文档解析

文档处理模块接收已上传文件，提取可用文本，进行清洗和分段，并保留文档名称、片段位置等来源信息。解析失败时记录明确状态，避免无效内容进入知识检索链路。

### RAG 知识检索

RAG（检索增强生成）模块将用户问题转换为检索请求，从知识片段中召回最相关内容，并将片段及其来源作为上下文提供给大模型。检索结果必须保留与原始文档的关联，以支持答案引用和核对。

### 大模型调用

后端通过独立的模型调用边界访问大模型。输入包含用户问题、检索到的知识上下文和回答约束；输出为面向用户的回答。未检索到充分依据时，模型应明确提示信息不足。模型密钥仅保存在服务端配置中，不下发到前端。

### Docker

Docker 用于统一开发和验收运行环境，承载前端、后端和 PostgreSQL 等必要服务。容器编排文件及镜像构建文件将在对应开发阶段补充，本次仅预留 `deploy/` 目录。

## 模块边界

```text
Vue 前端
   │ HTTP API
   ▼
FastAPI 后端
   ├── 文档处理 ──► 文档解析与分段
   ├── 知识检索 ──► PostgreSQL 中的知识片段
   ├── 问答服务 ──► 大模型服务
   └── 历史记录 ──► PostgreSQL
```

## 核心问答数据流程

1. 用户在 Vue 前端输入能源运维问题。
2. 前端将问题发送至 FastAPI 问答接口。
3. 后端对问题进行基本校验，并交给 RAG 知识检索模块。
4. 检索模块从 PostgreSQL 中召回相关知识片段及其文档来源。
5. 后端将用户问题、召回片段和回答约束组合为大模型请求。
6. 大模型基于提供的上下文生成回答；依据不足时返回明确提示。
7. 后端保存问题、回答、引用来源和必要的状态信息。
8. FastAPI 将回答及引用返回前端，前端向用户展示结果。

## 非目标

当前架构不覆盖设备控制、实时监控、复杂权限、多租户、工作流集成、模型训练或复杂智能体编排。这些能力不属于 MVP 范围。
